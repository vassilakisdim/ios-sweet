# Bonito port handoff

## Current state — 2026-11-15

- The phone has returned to Android 12 `SP2A.220505.008` and ADB enumerates it online. The CI shim image was accepted by ABL through `fastboot boot`; no partition was flashed or erased, and visible shim execution is still unconfirmed.
- Patch `0082-bonito-machine-config.patch` adds a `MACHINE_CONFIG=BONITO` scaffold, and the Bonito ADT no longer claims the `xiaomi,sweet` root match. It still reuses Sweet-derived kernel code and is not complete Bonito peripheral support. The machine-config patch correction is local and not yet pushed.
- Google's SDM670 DTS lists virtual timer PPI 3, corresponding to GIC INTID 19. XNU dispatches `43730585776` and `43731792820` were cancelled because the workflow requested retired `macos-14`. Run `43732154991` exposed stale patch `0082` contexts. Run `43734055796` applied the corrected patch and configured `BONITO`, but compilation failed because Xcode 16.4 IIG emits `IORPC.kernelContent` against the older XNU 8796 header, and libpthread/BearSSL staging was restricted to `SWEET`. Local fixes are patch `0083` and Bonito-enabled staging guards. No kernel compiled.
- Local fork branch: `port/bonito-bringup`, based on the user's fork commit `a563d834b366cafbb3dd912ce4b45c68b9a12480`; that fork is two commits ahead of upstream and includes the SDM670 shim/DTB work.
- Shim CI run `43724648790` built the initial image and experimental ADT; `43725471683` rebuilt the header-metadata variant; `43729672326` built the TWRP-matched LZ4/header/AVB image. No XNU kernel, iOS payload, or iOS root image exists yet.
- The initial 638,976-byte image (`95c4bc85557808900d70b46554a84566dbe51d483a6ca344c8e6bf2f05b75afe`) was rejected by ABL with `Unsupported`. Correcting its malformed Android 17 OS metadata to Android 12 did not solve the rejection. Adding an unsigned AVB footer and substituting TWRP's ramdisk/DTB while retaining a raw shim kernel also remained rejected.
- **ABL acceptance milestone:** a local diagnostic image using the shim kernel, TWRP-matched ARM64 Image fields (`text_offset=0x80000`, `image_size=0x3a84000`), the TWRP LZ4 frame profile, TWRP ramdisk/DTB/boot arguments, and a matching 64 MiB AVB-footer layout returned `Booting OKAY` from `fastboot boot`. SHA-256: `1e983adf8d4458f45ed01cdb34517708297b855b18d4795debe8aa7677f61cc3`. This confirms ABL acceptance and handoff only; it does not prove the shim displayed output or entered XNU.
- The successful diagnostic used independent 4 MiB LZ4 blocks with a frame checksum and a 51,591,192-byte expanded kernel file. A default LZ4 frame changed ABL's error to `Invalid Parameter`; matching TWRP's frame/header/AVB shape produced the successful handoff. The accepted test still used TWRP ramdisk and DTB, not the CI shim ramdisk and Bonito DTB.
- Immediately after `Booting OKAY`, neither ADB nor fastboot enumerated the handset. The on-screen state is pending user observation. No partition was flashed or erased. The earlier TWRP recovery auto-mounted `/data` and `/metadata` read-write, so incidental recovery writes cannot be ruled out.
- Device observed over ADB as Google Pixel 3a XL (`bonito`), Android 12 `SP2A.220505.008`, active slot `_a`, bootloader unlocked.
- Verified the reversible bootloader path: fastboot reports `product=bonito`, unlocked `yes`, slot `a`; `fastboot reboot` returned the phone to Android and ADB detected it again.
- The handset reports `dtb_idx=0` / `dtbo_idx=8`. Official TWRP 3.7.1_12-1 SHA-256 `e0781b592354a87ef8369cce36a0ed61e5bd751058d0eadf68c632c3568678d0` matched TeamWin's checksum; `fastboot boot` returned `OKAY` and recovery ADB ran as root for the FDT and `/proc/iomem` read.
- Live data identifies two physical RAM banks and their reserved holes, the Samsung `sofef00` command-mode panel, and an enabled eMMC SDHCI controller at `0x7c4000`. TWRP DRM reports 1080×2160 `XB24` buffers with 4352-byte pitch, but these are separate from the boot splash buffer. See `PORTING.md` for details.
- Recovery returned to Android with `adb reboot`; ADB confirmed the same Android 12 build and active slot. TWRP auto-mounted `/data` and `/metadata` read-write; no partition was flashed or erased, but incidental recovery writes cannot be ruled out.
- Initial hardware inventory and implementation sequence are in [`PORTING.md`](PORTING.md); structured observations are in [`device.json`](../../targets/bonito/device.json).
- The host has ADB/Git, no WSL distribution, and no AArch64 toolchain on `PATH`; GitHub Actions is the cross-build path. The XNU workflow is macOS-based.
- Main engineering blockers: a Bonito XNU platform target and memory-safe ADT, framebuffer handoff details, eMMC/SDHCI support, and Bonito input/display drivers. Sweet's current UFS root path is incompatible with Bonito's `/dev/block/mmcblk0`.
- `tools/mkadt.py --bonito` is now an experimental ADT staging profile. It emitted an 8,340-byte ADT; structure inspection confirmed RAM `0xa2000000–0x17e2c0000`, the 36 MiB splash reservation, 1080 × 2160 geometry, and cluster IDs 0 for CPUs 0–5 / 1 for CPUs 6–7. It omits UFS. The 4320-byte ABL splash stride remains an explicit unverified candidate; TWRP's 4352-byte recovery pitch describes other buffers.
- The CI artifact from run `43729672326` is 64 MiB, SHA-256 `f10897eb94f338d6bf977720eedd4bdc12b1d279565481692d561489c48026`, with a v2 header, TWRP-matched LZ4 frame, 51,810,304-byte pre-footer payload, and unsigned AVB hash footer. `fastboot boot` returned `Sending OKAY` and `Booting OKAY` using the CI image with the repository's Bonito DTB and shim ramdisk.
- After the CI image handoff, both ADB and fastboot listings were initially empty. A later read-only check found the phone online over ADB in Android 12 again. The screen state during the temporary shim boot was not recorded. No partition was flashed or erased.
- Local checks passed: the pinned AOSP packer plus repository unpacker round-tripped a dummy boot-header-v2 image, the Bonito ADT assertions passed, and `tools/validate-repo.py` validated all 81 patch files, 16 Python scripts, and 7 shell scripts. The new source build and CI workflow have now reproduced the accepted image layout.
